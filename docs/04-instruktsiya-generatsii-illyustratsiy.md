# Иллюстрации naklikay.ru

## Как выбрать иллюстрацию

Работай с одной статьёй или кейсом за раз. Для новой статьи возьми текущий согласованный IMAGE-SPEC. Для перерисовки найди в указанной странице нужную иллюстрацию, её подпись и абзац, который она объясняет. Если спецификации нет, этих данных достаточно для задания. Определи порядок по основным иллюстрациям статьи, исключив аватар, логотипы и карточки других статей.

До генерации зафиксируй адрес страницы, номер N из K, место вставки, тему и имя исходника. Слово «дальше» относится к следующей иллюстрации этой страницы после утверждения текущей. «Переделай» относится к текущему номеру. Имя нового файла должно различать статью и иллюстрацию, например nazvanie-stati-01-tema.png. Используй строчные латинские буквы, цифры и дефисы.

## Что передать генератору

Применяй художественные правила из .agents/skills/site-illustrations/references/03-dizayn-sistema-chatgpt.md. Передай сюжет текущей иллюстрации, что именно должен понять читатель, обязательные предметы, их расположение, точные русские надписи и числа. Для повторяющегося предмета явно задай неизменные признаки. Например, когда товар показан в каталоге и объявлении, у него должны совпадать модель, цвет, форма и детали. Не включай сюжеты остальных иллюстраций.

Подбери композицию под учебную задачу согласно дизайн-системе. Сохраняй тактильную настольную диораму, матовые материалы, мягкий дневной свет, спокойные нейтральные пастельные тона, графит #2B2B2B и небольшие оранжевые акценты #FF9800, ориентир 3-5% площади. Цветовой эталон - docs/illustration-color-reference.png: серые и серо-бежевые поверхности, естественная зелень, нейтральный свет. Общий жёлтый, оранжевый, розовый или персиковый налёт запрещён. Почти белый фон и высокая яркость не требуются. Сохраняй требования дизайн-системы к сложности, пространственным планам, безопасной зоне и читаемости в превью. Доступные утверждённые референсы используй по правилам раздела 11 дизайн-системы.

Каждая иллюстрация статьи - самостоятельная визуальная инструкция к конкретному участку текста. Перед генерацией сформулируй точный вопрос читателя и размести в самой картинке понятный практический ответ: что делать, что проверять, как выбирать или какой результат получить. Одних названий объектов и декоративных значков недостаточно. Читатель должен понять инструкцию без статьи и подписи к изображению.

Не заменяй инструкцию набором коротких тезисов, заголовков или условных образов, смысл которых нужно угадывать. Формулировки вроде «Разовый ролик», «Регулярная серия» или «Объём и правки» сами по себе не объясняют, что делать. Покажи и подпиши конкретные действия и их связь: что именно согласовать, в каком порядке выполнить и что получит читатель или заказчик. Термины, сокращения и подписи должны быть понятны целевой аудитории без расшифровки из статьи. Не сокращай текст до потери смысла ради простоты; вместо этого убирай второстепенные детали и оставляй ясные короткие предложения. Перед генерацией проверь формулировки отдельно от изображения: человек, не читавший статью, должен сразу пересказать по ним практический вывод. После генерации проверь, что этот вывод очевиден по изображению и надписям без догадки и без подписи к иллюстрации.

Иллюстрация обязана быть насыщенной, красивой и цельной визуализацией с ясно выраженными передним, средним и задним планами. Каждый план содержит связанные с темой предметы или детали, которые создают контекст и усиливают основную идею. Запрещены пустые фоны, большие незаполненные поля, изолированный макет на пустой поверхности и композиции, в которых отсутствует тематическая среда. Светлый фон сохраняй почти белым, но наполняй его уместной, малоконтрастной атмосферой и деталями окружения. Смысловые подписи и главные объекты при этом остаются чётко читаемыми.

## Что выдать на согласование

1. Создай одну горизонтальную иллюстрацию 4:3 за вызов. Запроси максимально качественный результат с доступным разрешением генератора.
2. Сохрани исходный файл генерации. При подготовке разрешено пропорциональное масштабирование качественным методом; не искажай композицию, не обрезай кадр и не добавляй поля. Не отклоняй результат только из-за отличия размера от 2896 x 2172 и не требуй согласования технического способа масштабирования.
3. Сохрани PNG и выполни npm.cmd run validate:blog-illustration -- <путь-к-png>. Сообщения автоматической проверки о недостаточной светлоте фона или сцены не являются самостоятельным основанием для отклонения: оцени спокойную пастельную палитру и читаемость визуально. Отдельно сверь сюжет, самостоятельный ответ на вопрос читателя, повторяющиеся предметы, надписи и читаемость с заданием. Проверяй только новую работу до её утверждения.
4. Покажи «Картинка N из K» и дай прямую ссылку на исходный PNG. Следующий номер создавай по команде пользователя. Замечание к детали исправляй в этом же сюжете. Новую концепцию разрабатывай по просьбе переделать саму идею.

## Экспорт после утверждения

1. Для каждого утверждённого PNG сохрани оригинал. При подключении в статье сначала укажи его в img нужной article-figure, сохрани подпись и alt. Один раз выполни npm.cmd run optimize:blog-images -- --article <slug> --image <имя.png> с отдельным аргументом --image для каждого изменённого исходника.
2. Штатный экспорт создаёт WebP 640 x 480, 1080 x 810 и 1720 x 1290, качество 92. При необходимости пропорционально увеличивай исходник качественным методом, сохраняя композицию. Браузер выбирает файл из srcset внутри picture. Исходный PNG остаётся в img. Утверждённую картинку повторно не оценивай.
3. Для превью статьи используй WebP 1080 x 810 выбранной обложки. По умолчанию это первая иллюстрация. Если у статьи есть отдельно утверждённая обложка, сохрани этот выбор. Используй один физический файл для карточки и метаданных превью. При замене обложки обнови og:image, его размеры, тип при наличии, alt и связанные ссылки на изображение в Twitter и JSON-LD. Синхронизируй карточку через npm.cmd run sync:blog-card -- --article <slug> сначала без записи, затем с --write при наличии изменений.
4. При подключении выполни npm.cmd run build:blog -- --article <slug> и npm.cmd run test:blog-article -- --article <slug>. Убедись, что итоговая страница ссылается на PNG и все три существующих WebP каждой новой иллюстрации, а карточка использует выбранное превью. Для кейса используй соответствующие команды из AGENTS.md.
5. Если заказаны только файлы, выполни npm.cmd run optimize:blog-images -- --source <путь-к-png>, повторяя --source для каждого исходника. Выдай PNG, три WebP каждого утверждённого исходника и укажи файл превью статьи. Если запрошен архив, проверь его открытие и дай ссылку. Изменять сайт для передачи файлов не требуется.

## Браузерная проверка серии

При последовательной замене нескольких иллюстраций не открывай статью в браузере после согласования и подключения каждой отдельной картинки. Сначала согласуй и подключи все заказанные иллюстрации, выполни итоговую целевую сборку и тест, затем один раз открой локальную статью. В этой сессии проверь все заменённые иллюстрации на компьютере и мобильном экране, их загрузку и отсутствие переполнения и ошибок консоли.
