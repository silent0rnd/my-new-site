# Правила работы с проектом

## Изменения
- Выполняй только задачу пользователя. Не делай посторонних исправлений, аудитов, рефакторингов и «улучшений».
- Не удаляй и не отключай существующие файлы, контент, стили, функции, скрипты, анимации и зависимости без прямого разрешения.
- Перед правкой читай актуальный целевой файл; изменяй только нужные фрагменты, сохраняя чужие незавершённые изменения. Код проекта важнее документации.

## Git и копии
- **Без прямой команды не выполняй никаких Git-команд**, включая `status`, `diff`, `log`, `commit`, `stash`, `restore`, `reset`, `pull`, `push`; не работай с GitHub.
- Не создавай `.bak`, резервные копии, снимки проекта и дубликаты исходников без прямой команды. Существующие оригиналы изображений, используемые страницами, не удаляй.

## Навигация и проверки
- Используй пути из задачи. Если путь неизвестен, прочитай только нужный раздел `project-map.md` и ищи в соответствующей папке. Не сканируй весь проект и не выводи большие списки/файлы.
- Не создавай и не обновляй общий индекс файлов.
- Запускай только необходимые для конкретных изменений сборки и тесты. Не повторяй успешные проверки; браузер и общий аудит — лишь при обоснованной необходимости.
- Для статей следуй навыку `blog`: создание и редактирование — разные сценарии.
- Несвязанные ошибки не исследуй и не исправляй; укажи их в итоговом отчёте.

## Экономия контекста
- До чтения файлов определи сценарий задачи и затрагиваемый контракт. Не выполняй шаги другого сценария.
- Не выводи целые HTML, большие исходники, минифицированные строки и результаты широкого поиска. Извлекай только нужные разделы, совпадения, счётчики, пути и краткие итоги.
- Не передавай полный HTML, исходный текст статьи или большой патч через вывод команд. Для полной замены статьи используй штатный преобразователь: сначала режим проверки, затем запись теми же аргументами.
- Ищи по точному пути, slug или имени файла. Используй ограничение совпадений и вывод только имён файлов; не сканируй весь блог без доказанной необходимости.
- Сначала собери все требуемые изменения, затем внеси их одним основным патчем. Успешные проверки не повторяй.
- Объединяй целевые проверки в один итоговый валидатор. Сборку, оптимизатор, глобальные тесты и браузер запускай только по условиям навыка или прямому требованию.
- Если штатная команда завершилась ошибкой, остановись и исправь эту ошибку до сборки и браузера. Не продолжай цепочку с частично подготовленными файлами.
- В браузере используй одну сессию после завершения правок и проверяй только изменённый визуальный участок. Скриншоты делай при визуальном риске, а не для каждого контрольного пункта.
- Ограничивай промежуточные сообщения началом работы, существенной проблемой и итогом.
- Ориентир процесса: до 10 инструментальных действий для редактирования и до 15 для новой статьи. Превышай ориентир только при ошибке, обязательной дополнительной проверке или внешнем ограничении.

## Отчёт
- Кратко перечисли реально созданные, изменённые, удалённые файлы и результаты проверок. Если удалений нет, напиши `Удалено: ничего`.
