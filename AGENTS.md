# Правила внесения изменений

При любых изменениях файлов проекта обязательно:

1. После выполнения задачи выводить отдельный раздел "Изменения".
2. В этом разделе перечислять ВСЕ измененные файлы.
3. Для каждого файла кратко указывать:
   - что было добавлено;
   - что было изменено;
   - что было удалено.
4. Отдельно явно сообщать обо всех удалениях:
   - файлов;
   - функций;
   - скриптов;
   - CSS-стилей;
   - HTML-блоков;
   - анимаций;
   - обработчиков событий;
   - зависимостей.
5. Никогда не удалять существующий функционал, анимации, визуальные эффекты или скрипты, если пользователь прямо не попросил это сделать.
6. Если для решения задачи кажется необходимым удалить или существенно изменить существующий функционал, сначала сохранить его и выбрать решение без удаления.
7. Не выполнять несвязанные с задачей рефакторинги и "улучшения".
8. После каждого ответа, в котором были изменены файлы, использовать формат:

## Изменения
- `путь/файл.ext` - что изменено
- `путь/другой-файл.ext` - что изменено

## Удалено
- Ничего

Если что-либо удалено, перечислить это явно вместо "Ничего".

# Naklikay

Статический сайт специалиста по контекстной рекламе с кейсами, блогом и собственными сервисами.

## Команды

| Команда | Что делает |
|---------|------------|
| `npm.cmd run build:blog` | Пересобрать архив блога |
| `npm.cmd run build:cases` | Пересобрать страницы кейсов |
| `npm.cmd run test:blog` | Проверить блог |
| `npm.cmd run test:cases` | Проверить кейсы |

## Как здесь работает Autopilot

Прогон ведётся навыком `/autopilot`. Требования, спецификация и таски находятся в `.autopilot/`.
Прогресс отображается в `.autopilot/dashboard.html`. Требование из `manifest.md` может снять только пользователь.

Если работа продолжается - скажи «продолжи автопилот»: состояние поднимется из `.autopilot/state.js`.
