# Статьи блога Naklikay

Следуй `AGENTS.md`. Сначала выбери сценарий: A - новая статья; B - существующая статья. Не смешивай сценарии и сохраняй утверждённые текст, SEO и изображения.

## Общие правила
- До чтения файлов определи ветку задачи: новая статья, полная замена, абзацы, SEO, H1/карточка, H2/H3, изображения или вёрстка. Из минифицированного HTML выводи только значения, счётчики или фрагменты до 300 символов.
- Перед записью собери зависимые изменения целевой страницы: title/description, OG, Twitter, JSON-LD, даты, canonical, главное изображение и карточку.
- Внешние ссылки не публикуй: преобразователь должен оставить только их видимый текст без `<a>`. В новую или полностью заменяемую статью добавляй 2-4 проверенные внутренние ссылки с осмысленными анкорами и новой вкладкой. При точечной правке ссылки без запроса не добавляй.
- Списки оформляй `<ul>/<ol><li>`. Служебные `Title:`, `H1:` и маркеры исходника не публикуй. В изменяемом тексте связывай многозначные числа, суммы и единицы через `&nbsp;`, а диапазоны пиши с дефисом.
- Сохраняй `.article-lead`. В новой или полностью обновляемой длинной статье выделяй 1-3 вывода через `<p class="content-key-point">`. Блок «Коротко» оформляй как `<aside class="content-key-point">` с `<p>` и `<ul><li>` после вступления и до TOC. Используй оранжевую линию без фона и рамки, 25-31 px на desktop и 24 px на mobile; не включай блок в TOC и не применяй его к FAQ, формулам и обычным абзацам.

## A. Новая статья
1. По шаблонам из `templates/` создай `blog/<slug>/index.html` и карточку в `blog/index.html`. Замени все плейсхолдеры, сохрани оболочку, стили и скрипты; другие статьи вручную не меняй.
2. Добавь один H1, логичные H2/H3, title/description, self-canonical, `index,follow`, Open Graph, favicon `/assets/avatar-donut.svg?v=2`, `BlogPosting` или `Article`, `BreadcrumbList`, автора и дату.
3. После текста добавь `.article-author`: `../../assets/author-avatar.jpg`, Максим Мирошников, «Специалист по платному трафику и Яндекс Директу», текст о 10-летнем опыте и ссылку `../../#about` с текстом «Подробнее обо мне». Сохрани автора в JSON-LD.
4. Вставь только переданные изображения и один раз запусти `npm.cmd run optimize:blog-images -- --article <slug>`. Сохрани оригиналы; WebP 640/1080/1720 создавай без увеличения.
5. Один раз запусти `npm.cmd run build:blog -- --article <slug>` для архива, sitemap, TOC, `.related-articles` и `scripts/blog-related-topics.json`. Сгенерированные блоки вручную не правь.
6. Один раз выполни `npm.cmd run test:blog-article -- --article <slug>` и `npm.cmd run test:related-articles -- --article <slug>`.
7. Полные `test:related-articles`, `test:blog-toc`, `test:favicon` и `test:blog-images` запускай только после изменения их общей логики или при локальной проблеме.

## B. Существующая статья
1. Изучи целевой `blog/<slug>/index.html` и указанные материалы. URL, неизменённые элементы и другие страницы не трогай.
2. Для полной замены из TXT с `<SEO-META>` и `<ARTICLE-BODY>` сначала запусти без записи `npm.cmd run update:blog-article -- --article <slug> --source <txt> --image <путь>`, повторяя `--image` для каждого файла. Проверка должна подтвердить slug, структуру, количества заголовков и изображений, конфликты имён и размеры. После успеха повтори ту же команду с `--write`.
3. Ограниченным извлечением проверь title/description, OG, Twitter, JSON-LD, canonical, даты и главное изображение. При изменении H1, description или главного изображения выполни `sync:blog-card` сначала без записи, затем с `--write`.
4. Для заменённых изображений один раз запусти `optimize:blog-images` со всеми именами из результата преобразователя, затем `npm.cmd run build:blog -- --article <slug>`.
5. После полной замены запусти `npm.cmd run test:blog-refresh -- --article <slug> --source <txt>`, повторяя `--old-image` для удалённых изображений. При изменении изображений, таблиц или вёрстки дополнительно один раз запусти `npm.cmd run test:blog-refresh:visual -- --article <slug>`.
6. Для замены только абзацев потребуй одно совпадение исходного фрагмента и проверь отсутствие старого и наличие нового. Если H2/H3, метаданные и изображения прежние, сборка, оптимизатор и браузер не нужны.
7. После изменения H2/H3 один раз запусти целевую сборку и проверь заголовки и ссылки TOC.
8. При изменении только title, description или `dateModified` синхронизируй SEO-поля без сборки, если H1 и карточка прежние.
9. При изменении H1 или карточки синхронизируй карточку и зависимые SEO-поля, один раз запусти целевую сборку и проверь затронутые карточки и рекомендации. `lastmod` чужих URL не меняй.
10. Если изображения не менялись, не запускай оптимизатор и не меняй их разметку. Для добавленных или заменённых файлов один раз запусти `npm.cmd run optimize:blog-images -- --article <slug> --image <имя или src>`, повторяя `--image` в одной команде. Проверь `<picture>` только у выбранных файлов и неизменность старых фигур.

## Изображения и проверки
- Новые изображения считай дополнением, если замена не указана прямо. При замене удаляй старые ссылки и файлы только после проверки их использования. Не придумывай дополнительные иллюстрации.
- Локальные изображения без запроса на анализ не открывай: проверяй имена, количество, размеры, пропорции и при необходимости хеши. Перед генерацией или перерисовкой изучи бриф, исходники и дизайн-систему.
- Для иллюстраций используй `<picture>` с WebP 640/1080/1720, `sizes="(max-width: 720px) calc(100vw - 36px), 860px"` и исходным JPG/PNG в `<img>`. Сохрани alt, width/height и пропорции. Строку `Иллюстрация № N` после изображения не публикуй; следующую строку оформи как `<figcaption>`. Изображение первого экрана не делай lazy; ниже используй `loading="lazy"` и `decoding="async"`. Не обрабатывай старые изображения, логотипы, автора и похожие статьи без запроса.
- Итоговый валидатор должен проверить затронутые H1, ссылки, метаданные, JSON-LD, HTML, изображения и артефакты `�`, `undefined` и плейсхолдеры. Браузер нужен только при визуальных изменениях; проверяй desktop, mobile, lazy-загрузку, переполнение и консоль в одной сессии.

## Отчёт
Кратко укажи URL, результат, созданные, изменённые и удалённые файлы, проверки и проблемы. Для новой статьи также укажи H1, title/description, архив, sitemap и три рекомендации. Заверши точным предложением для журнала.
