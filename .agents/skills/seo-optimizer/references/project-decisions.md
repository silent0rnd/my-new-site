# Подтверждённые рабочие решения из истории проектов SEO и Вебвизор

Материал для методики, а не текущий отчёт. Ряд решений получен из прошлых разговоров, не из непосредственного полного экспорта всех чатов.

1. **Мониторинг обязателен перед усилением опубликованной статьи.** В октябре 2026 закреплено требование всегда сверять Google-таблицу `SEO мониторинг naklikay.ru`, особенно `Журнал усилений`, 7/28-дневные показатели, запросы, историю страниц и проблемы.
2. **Приоритет реального URL+кластера.** Основная фраза в карте интентов - контрольная, а не весь спрос. Приоритет запросам в позициях 4-10, затем 11-20 при заметном спросе; удачную страницу не переписывать автоматически.
3. **Каннибализация требует подтверждения, не скриншота.** Ручные проверки инкогнито полезны только для выдвижения гипотез. Анализ нескольких дат/регионов и фактических пар запрос-URL обязателен.
4. **Не смешивать Яндекс и Google.** GSC служит независимой проверкой, отдельные показатели; отсутствующие данные не равны нулю. При сбоях PRO обычный SEO-аудит контента и техники допустим, но оценка свежих URL-позиций ограничена.
5. **При сомнительном URL сначала первичные источники.** Когда сайт и canonical корректны, но таблица/SEO-карта содержит старый URL, исправлять нужно реестр, не ставить 301 на сайте.
6. **Разграничение страниц предпочтительнее массового слияния.** Коммерческие страницы директолога, настройка/ведение, федеральные и региональные интенты - разные задачи, пока обратное не доказано.
7. **После изменений выдержать контрольное окно.** Не давать новую рекомендацию просто потому, что показатели ещё не обновились после правки. Исторический пример: страница, изменённая 19.10, в проверке 13.11 не подлежала слиянию без фактического подтверждения; повторно сверить после 16.11.
8. **Технический простой ≠ массовая деиндексация.** После аварии хостинга сначала проверить реальные HTTP, индексацию и свежесть отчётов; не инициировать переобход всех страниц автоматически.
9. **У проекта уже есть SEO-мониторинг.** Не создавать второй «технический watcher» или второй журнал; использовать существующие данные и систему. Историческое ограничение на AI-метрики уточнено: достоверные Bing AI Performance разрешены отдельной категорией источника, но не искусственным общим GEO KPI и без самостоятельного дублирующего мониторинга.
10. **Результат должен быть практическим.** Пользователь хочет готовый текст, точные замены для кодового агента и архив файлов; статьи без обоснованной потребности не переписывать, решения не превращать в бесконечное обсуждение.

## Примеры тематических кластеров для проверки, не готовые вердикты

- «Частный директолог», «Частный специалист Яндекс Директ», «Директолог для бизнеса» - сначала назначение основной федеральной страницы и сопоставление интентов.
- «Яндекс Директ нет заявок» и «Почему Яндекс Директ не даёт заявки» - проверить совпадение задач и реальных запросов.
- «Контекстная реклама онлайн-школы» и «Яндекс Директ для онлайн-школы» - возможное пересечение, но не доказанная каннибализация.
- Региональные запросы «директолог Ростов-на-Дону» не сводить механически к федеральному кластеру.

Историческая SEO-карта и численность URL могли измениться. Брать только **актуальный реестр из репозитория**, проверенный по нынешнему sitemap/живому сайту, а не архивные числа.
