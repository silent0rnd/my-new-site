# Каннибализация и карта интентов

## Базовое различие

- **Смысловое пересечение**: статьи похожи тематически/по Title/H1. Не равно доказанной каннибализации.
- **Неправильный URL в выдаче**: по целевой фразе показана другая наша страница; единичное наблюдение не доказывает ущерб.
- **Подтверждённая каннибализация**: повторяющееся конкурирование нескольких URL по одному поисковому интенту с достаточными показами/данными и негативным эффектом для целевой страницы.

## Диагностика

1. Составить пару/группу спорных URL и актуальный кластер запросов.
2. Сверить целевое назначение страниц по карте интентов (группа 1/2/3), аудиторию и различия: услуга/специалист/инструкция/отрасль/регион.
3. Проверить реальные `query + URL` показы, клики, позиции по нескольким датам/окнам; учитывать регионы и сезонность. При отсутствии PRO прямо ограничить достоверность.
4. Проверить, какие URL реально индексируются, какие канонические, что в sitemap, куда ведёт перелинковка; не путать устаревший реестр с живым сайтом.
5. Посмотреть Яндекс и Google по целевому региону, выдачу и сниппет. Ручная проверка инкогнито - вспомогательная, зависит от региона и времени.
6. Решить, является ли пересечение конфликтом или допустимо иметь отдельные страницы для разных намерений.
7. Записать одну рекомендацию для каждого URL: `сохранить`, `наблюдать`, `разграничить интенты`, `укрепить целевой URL`, `объединить после согласования`, `301 после проверки и согласования`.

## Как выбирать основную страницу

Учитывать: (a) реальный спрос и показы по нужному интенту; (b) полезность и полноту; (c) историю позиций/кликов; (d) коммерческую ценность; (e) уже существующие ссылки, кейсы, региональность; (f) техническое состояние.

- Для федеральной услуги и Ростова не назначать один URL автоматически: определить реальную географию и намерение. Не переименовывать региональный URL в федеральный без доказательств.
- Если одна страница уже ранжируется и недавно редактировалась, не вытеснять её на основании одного инкогнито-наблюдения.
- Если два материала решают разные задачи (например, «частный директолог», «директолог для бизнеса», инструкция по настройке), сохранить их и явно развести назначение/Title/H1/связи.
- Только при доказанной избыточности и отсутствии самостоятельного интента рассматривать объединение/301 после полного техаудита и отдельного разрешения.

## Примеры из истории проектов (не свежий аудит)

- В проверке 13.11.2026 рассматривались 63 запроса в 19 группах. Массовое объединение не рекомендовано: само наблюдение нескольких URL в ручной выдаче не доказало каннибализацию.
- Указаны кандидаты на дополнительную диагностику: «Яндекс Директ нет заявок / не даёт заявки»; «контекстная реклама / Яндекс Директ для онлайн-школы». Это не автоматические рекомендации по 301.
- В отдельной паре статей о Директе 13.11.2026 подтверждено смысловое дублирование, но доказательств поисковой каннибализации недостаточно; после переработки 19.10 рекомендовалось наблюдение и повторная проверка после 16.11.

Эти примеры не заменяют повторную проверку текущих данных. Не брать исторический статус как вечный.
