# Сопоставимость разных источников и данные для SEO-решений

## Три измерения качества

**Происхождение:** источник, property, дата получения, ссылка на выгрузку
или report_id, разрешённые фильтры, исходная схема.

**Полнота:** начало/конец интервала, фактическая последняя дата, задержка,
покрытие по URL, статус `complete / partial / delayed / failed / manual`.

**Гранулярность:** сайт, URL, поисковая фраза, дата, страна/регион,
устройство/поверхность и методика позиции, если доступны. Гранулярность
нельзя «достроить» из общего отчёта без фактов.

## Запреты

- Не суммировать показы/клики из Яндекса, GSC, Bing как единую органику.
- Не усреднять позиции разных систем; не складывать метрики запросов и URL
  после джойна без проверки повторения строк.
- Не сводить Search Performance и AI Performance Bing в одну метрику.
- Не считать пропуски, задержку индексации или отсутствие AI-отчёта нулями.
- Не утверждать причинность результата на основе одной даты SEO-правки.
- Не игнорировать PRO/не-PRO различия в Яндексе и лимиты API/выборку.

## Анализ изменений

Сопоставлять одинаковые по длительности и фильтрам завершённые окна
`последние 7 vs предыдущие 7`, `последние 28 vs предыдущие 28`.
Для изменений в источниках разной свежести окна выбирают отдельно.

Для опубликованной страницы базовые записи содержат источник, URL,
дату публикации правки, дату обновления метрик, полный кластер запросов,
показатели до/после, изменения соседних страниц, ограничения, контекст
сезонности/спроса. Изменение CTR проверить на уровне запросов и позиции.

Рекомендации должны отвечать: `какой URL`, `какой запрос/интент`, `какие
данные и откуда`, `что изменить`, `почему`, `какие риски`, `когда проверить`.
