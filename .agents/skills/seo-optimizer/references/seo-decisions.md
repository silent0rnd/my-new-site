# Дерево решений: менять, наблюдать или не трогать

## Три уровня уверенности

**Подтверждённый факт:** первичный источник с датой/URL/показателем, или живой сайт/код ответа. **Гипотеза:** возможная причина падения, сниппета, дубля и т.д. **Решение:** предполагаемое вмешательство с эффектом и риском.

Не выдавать гипотезу за факт. По умолчанию без достаточных данных - «наблюдать/проверить», а не «переписать/объединить».

| Сигнал | Что сначала проверить | Допустимый исход |
|---|---|---|
| 4-10 по релевантному кластеру с показами | контент/интент, топ, история правок, каннибализация | небольшое содержательное усиление, релевантные ссылки, ответ в начале |
| 11-20 с реальным спросом | соответствие интенту, техническая доступность, конкуренты | устранить недостающий полезный блок или разрыв интента |
| Высокая позиция и низкий CTR | достаточно ли показов, SERP, сниппет и запросы | точечно проверить Title/Description/вступление либо ничего не менять |
| Падение за 7 дней | полные 28 дней, сезонность, смена запросов, ошибки сбора, журнал | наблюдать либо исправить подтверждённую проблему |
| Новая страница без показов | возраст страницы, HTTP, индексирование, sitemap | дождаться индексации/проверить технику, не удалять |
| Похожий соседний URL | query+URL по датам, карта интентов и различия | разграничить, оставить, наблюдать; 301 только после строгой проверки |
| Несовпадение URL в таблице | живой URL, canonical, sitemap, внутренние ссылки | исправить реестр, если сайт уже правильный |
| Устаревшие/неполные данные PRO | свежесть других каналов/таблиц | контентный/технический аудит с оговоркой, без массовых SEO-выводов |
| Подтверждённые HTTP/robots/canonical проблемы | код, URL, целевое назначение | план технического исправления и повторная проверка |

## Приоритет

1. Критические фактические проблемы индексации/доступности важных страниц.
2. Коммерческие страницы группы 1 (частный директолог, настройка/ведение Директа и пр.) с доказанным потенциалом; реальная бизнес-ценность важнее «просто много показов».
3. Группа 2, группа 3, при наличии значимого спроса/потерь.
4. Изолированные низкочастотные фразы и малоизмеримые эффекты - наблюдать.

## Контроль изменений

- Перед правкой запиши baseline: URL, полный кластер, период, дата, метрики, недавние изменения, индексирование, соседние URL.
- Сформулируй *одну проверяемую гипотезу* на конкретную правку; не менять одновременно всё, если иначе нельзя понять эффект.
- После одобрения зафиксируй точные изменения и дату в существующем `Журнал усилений`/проектном журнале; не ломай чужую структуру и не придумывай записи об уже сделанном.
- После изменения проверь видимый HTML, метаданные, ссылки и что нет непреднамеренных регрессий; переобход по необходимости, без массовой постановки всех URL.
- Сравни показатели после того, как сформировано достаточное сопоставимое окно и данные обновились. Если данных пока нет - не объявляй рост/падение.

## Что не делать

Не плодить однотипные статьи под минимальные вариации запроса. Не менять canonical/URL/301 за несовпадение в реестре. Не использовать устаревший скрипт как доказательство свежести данных. Не увеличивать объём текста просто ради SEO. Не внедрять выдуманные GEO KPI или второй независимый мониторинг. Подтверждённые Bing AI Performance метрики допускается учитывать отдельно от обычного поиска и только после проверки источника и схемы существующей системы.
