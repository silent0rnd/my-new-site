# Метод анализа SEO-показателей и выбор приоритетов

## Порядок при аудите сайта

1. Зафиксировать актуальные даты и полноту данных.
2. Общая динамика: последние 7 дней против предыдущих 7; 28 дней против предыдущих 28 при наличии; показы, клики, CTR, средняя позиция, видимые URL и число реальных запросов.
3. Сегментировать по карте интентов: группа 1 (коммерческие страницы, главный приоритет), группа 2 (коммерческо-информационные), группа 3 (информационные/служебные).
4. Выделить новые/потерянные запросы, рост и падение URL, важные страницы без видимости, индексирование.
5. Сверить «Журнал усилений»: не путать естественный лаг после обновления с провалом и не запускать повторные правки через несколько дней.
6. Проверить соответствие запроса и URL, гео и случаи непредназначенной страницы; при необходимости углубиться до мини-аудита URL.
7. Выпустить список конкретных действий по уровню риска и бизнес-приоритету.

## Порядок при аудите URL

1. Прочитать публикацию/HTML, определить назначение URL в карте, основной поисковый интент и дату последней существенной правки.
2. Выгрузить **весь доступный значимый кластер реальных запросов для URL**, а не только контрольную «Основную фразу»; отметить долю запросов без привязки URL, если она есть.
3. Для запросов разбить позиции на `1-3`, `4-10`, `11-20`, `>20` и неранжирующиеся; привязать показы и клики. Фокус при наличии спроса: 4-10, затем 11-20, с оглядкой на бизнес-ценность.
4. Проверить соседние URL по тем же запросам. Вердикт «каннибализация» только после проверки из [cannibalization.md](cannibalization.md).
5. При высокой позиции, но слабом CTR проверить объём показов, тип выдачи, брендовые/небрендовые запросы, интент, Title/Description и видимый сниппет; Google и Яндекс анализировать отдельно.
6. При падении видимости сверить частоту, сезонность, сдвиг интента/позиции, индексацию, технические статусы, изменение группы запросов, историю правок и полноту дат. Не заключать «Title плохой» только по CTR.
7. Изучить текущие страницы в топе по важным запросам: тип результата (сервис/инструкция/коммерция/кейс), что решают, чего не хватает на нашей странице, какие элементы нужны, какой конкурентный интент.
8. Зафиксировать наблюдения и предложить **минимально достаточные** правки либо контрольный период без вмешательства.

## PRO и URL+query

Если есть PRO, использовать связку `дата | host | path | query | регион | клики | показы | позиция` и регион; построение URL из host+path после проверки формата. Не полагаться на случайный одиночный срез выдачи. При отсутствии PRO допустим анализ обычных данных с явным ограничением точности по конкретной паре URL+запрос.

## Интерпретация

- 2 показа и 0 кликов - не доказательство плохого Title, кейса, структуры или санкций.
- Изменение средней позиции всего URL может объясняться изменением состава запросов, а не ухудшением позиции по ключевому кластеру.
- CTR между запросами разной позиции/интента и разных поисковиков напрямую не сравнивать.
- Нулевые строки при пропуске выгрузки - не «нулевая органика».
- Контент с хорошими позициями без подтверждённой проблемы не переписывать ради обновления даты.
- Цель не «вывести всё в топ», а выбрать конкретный URL с измеримым потенциальным выигрышем и сохранить работающие запросы.
