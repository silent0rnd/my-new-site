# Задание агенту: интеграция правил статей naklikay.ru

Ты работаешь в существующем проекте сайта naklikay.ru. Этот ZIP - **пакет инструкций для расширения действующих навыков**, а не готовый новый сайт/статья и не команда публиковать контент.

## Цель

Научить текущего агента качественно создавать два типа SEO-материалов по методике проекта:

- `STANDARD`: практическая SEO-статья/статья-инструкция;
- `FORECAST`: продвижение отрасли с исследованием, расчётом рекламного бюджета и результатов, инструкцией по запуску рекламы, разделением реальных фактов и прогнозов.

Важны последовательность согласования с пользователем, доказательность чисел и фирменная система иллюстраций.

## Что проверить прежде изменений

1. Найди настоящие определения/`SKILL.md` и связанные файлы действующих навыков `seo-content`, `seo-content-brief`, `seo-page`, `seo-optimizer`, `blog`. Изучи, как они запускаются, связываются, какие уже есть проверки и какие обязанности пересекаются.
2. Найди локальные правила проекта (`AGENTS.md`, каталоги навыков и существующие инструкции), структуру сайта, формат хранилища контента и публикационный путь. Не предполагай расположение без проверки.
3. Перед редактированием сравни, что уже реализовано, с архивом и выдели недостающие требования. Не удаляй работающие алгоритмы, не заменяй существующие навыки шаблонными файлами.

## Что внедрить

1. Подключи `instructions/00-poryadok-raboty.md` как единый основной порядок этапов, применимый к новым и улучшаемым статьям.
2. В `seo-content` обеспечь распознавание `STANDARD` / `FORECAST`. Общие правила бери из `instructions/02-instruktsiya-dlya-seo-statey-final.md`; для FORECAST обязательно добавляй `instructions/instruktsiya-statya-prognoz-v17.md` и `instructions/05-sovmestimost-prognoza.md`.
3. Используй `seo-content-brief` для подготовки интента, исследования, структуры, расчётных допущений, планов H2/H3 и подробных `IMAGE-SPECS` до написания статьи. Его выход должен удовлетворять этапу 1 основного порядка.
4. `seo-optimizer` используй как контроль интента, каннибализации, метаданных, внутренних ссылок, качества выводов, фактов и отсутствия нейрошаблонов. Для FORECAST добавь независимый пересчёт CPC/CPL/CPA/CAC, перехода от лидов к продажам и проверку допущений.
5. `seo-page` подключай к существующей работе с отдельными страницами; для уже опубликованных URL сохраняй slug/canonical, авторский голос и работающие части. Не устраивай конкуренцию нескольких URL на один и тот же интент.
6. `blog` оставь ответственным за существующую сборку/создание/редактирование статей сайта. Публиковать и переписывать текущие страницы можно только по явной команде пользователя и после соответствующих этапов согласования.
7. Подключи правила изображений `instructions/dizayn-sistema-naklikay-aktualnaya.md` и `instructions/04-instruktsiya-generatsii-illyustratsiy.md`. **Одна команда = одна генерация**. Изображения появляются до полного текста. Финал только JPG 2896 x 2172 px, 4:3, качество 93%, латинские имена, проверка целостности и читаемости. Не имитируй готовность, если генератор недоступен.
8. Для внутренней перелинковки/каннибализации используй `references/sitemap.xml` как отправную точку, обязательно проверяя доступные актуальные исходники сайта и существование ссылок. Не придумывай URL.
9. Обеспечь хранение статуса текущей статьи/этапа, согласованных H2/H3 и цифр, списка `IMAGE-SPECS`, `IMAGE-STATUS`, принятых файлов и итоговых метаданных в существующем рабочем механизме проекта, без избыточных новых систем.
10. Организуй подключение исходных инструкций как справочных файлов текущего навыка (например, `references/` с корректными относительными ссылками) либо в принятом в репозитории формате. Не копируй весь объём в краткий front matter навыка.

## Критические ограничения

- **Не создавай шестой конкурирующий SEO-навык** ради этих двух типов статей. Дополни существующие, прежде всего `seo-content`, и настрой корректные передачи управления.
- Не переделывай текущую опубликованную статью и не публикуй сайт только ради настройки навыков.
- Не изменяй исходники этого ZIP. Копируй их как источники правды и добавляй адаптеры/ссылки, если это нужно.
- При конфликте инструкций приоритет у прямой команды пользователя, затем `00-poryadok-raboty.md`, затем общая инструкция и соответствующая дополнительная. По графике приоритет у актуальной дизайн-системы.
- Оригинальная v17 содержит устаревшие ссылки/порядок; `05-sovmestimost-prognoza.md` переопределяет именно их.
- Статья не должна содержать выдуманных кейсов, «средних по рынку» без исследования, несуществующих ссылок, неподтверждённого авторского опыта и рекламных штампов.

## Как проверить работу

Выполни проверки из `checks/proverka-navyka.md` без создания/публикации реальных статей и без реальной генерации картинок. Примеры могут использоваться как сухой прогон распознавания задач и остановки по этапам.

## Что предоставить по завершении

1. Перечень **фактически изменённых** файлов навыков/конфигурации и кратко, что изменено.
2. Связь каждого изменения с действующими пятью навыками.
3. Результат проверок из `checks/proverka-navyka.md` (прошло/не прошло; при проблемах указать конкретную).
4. Список зависимостей, если обнаружилось, что у агента нет поискового доступа, инструмента генерации изображений или возможности создавать JPG/ZIP. Не заявляй доступность инструментов без проверки.

**Не начинай писать статью без отдельной пользовательской темы/команды.**
